Schema-ändringar

1. Nya kolumner på projects

ALTER TABLE projects ADD COLUMN tracks_economy boolean NOT NULL DEFAULT true;
ALTER TABLE projects ADD COLUMN tracks_rot boolean NOT NULL DEFAULT false;
ALTER TABLE projects ADD COLUMN owner_user_type text;  -- cachat från profile vid skapande
-- Backfill: tracks_economy = (owner är proffs); tracks_rot = false (alla får aktivt välja)

2. project_shares — expires_at + new role_types

ALTER TABLE project_shares ADD COLUMN expires_at timestamptz;
-- role_type får nya värden: "owner", "co_owner", "pm_hired", "member", "client", "worker"
-- (worker är synonym till worker_access_tokens — för enklare query-uniform)

3. materials — paid_by

ALTER TABLE materials ADD COLUMN paid_by uuid REFERENCES profiles(id);
COMMENT ON COLUMN materials.paid_by IS 'Vem betalade — användbar i hemägar-projekt';

4. Ny tabell: access_log

CREATE TABLE access_log (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid REFERENCES projects(id) ON DELETE CASCADE,
  profile_id uuid REFERENCES profiles(id),
  action text NOT NULL,         -- 'view' | 'download' | 'edit' | 'denied'
  target text,                  -- e.g. 'budget.tab', 'task.123', 'file:ritning_v3.pdf'
  denied boolean DEFAULT false,
  created_at timestamptz DEFAULT now()
);
CREATE INDEX idx_access_log_project_created ON access_log(project_id, created_at DESC);
CREATE INDEX idx_access_log_profile ON access_log(profile_id);

5. get_project_data RPC (skiss)

CREATE FUNCTION get_project_overview(p_project_id uuid)
RETURNS jsonb
LANGUAGE plpgsql STABLE SECURITY DEFINER AS $$
DECLARE
  v_share project_shares;
  v_mode text;
BEGIN
  -- Hämta viewer's share för detta projekt
  SELECT * INTO v_share FROM project_shares
  WHERE project_id = p_project_id
  AND shared_with_user_id = get_user_profile_id();

  -- Härled mode från share
  v_mode := CASE
    WHEN v_share.role_type IN ('owner', 'co_owner') THEN 'full'
    WHEN v_share.budget_access = 'edit' THEN 'full'
    WHEN v_share.budget_access = 'view' THEN 'own'
    ELSE 'none'
  END;

  -- Returnera filtrerat JSON
  RETURN jsonb_build_object(
    'project', jsonb_build_object(
      'id', p.id, 'name', p.name,
      'total_budget', CASE WHEN v_mode = 'full' THEN p.total_budget ELSE null END,
      ...
    ),
    'tasks', (SELECT jsonb_agg(...) FROM tasks WHERE ...),
    'materials', ...
  );
END $$;

Claude Code-instruktioner · implementation i 5 steg

Föreslagen ordning för att minimera blockerings­risker:

01

Schema-migration först

Migrationsfil: add_team_v2.sql. Innehåller alla 5 schema-block ovan (projects-toggles, project_shares.expires_at, materials.paid_by, access_log-tabell, get_project_overview RPC). Backfill projects.tracks_economy till true för existerande projekt så inget bryts.

02

Mode-derivation + field-masking i datalagret

Skapa src/services/projectDataService.ts med wrappers runt alla supabase.from(...)-queries som tar viewer-context. Hooks som useTasksData, useMaterialsList, useBudgetData går via dessa istället för direkt mot tabellerna. Edge function get_project_overview för stora aggregat.

03

Wizard-refaktor

Byt InvitePath-typen till InvitePersona. Skriv om WizardStep1Path.tsx till 4 persona-kort. Ta bort packageToAccess.ts; ersätt med personaToAccess.ts. Lägg till InvitePreviewOverlay.tsx. Avskaffa InviteWorkerDialog.tsx efter migration av generateChecklists.

04

TeamTable v2 + Audit log

Lägg till persona-pill, mode-pill, last-active-kolumn. Implementera useLastActive(profile_id, project_id)-hook som läser från access_log. Bygg AccessAuditLog.tsx-tab. ProjectSetupDialog.tsx får två nya toggles.

05

Komponenter som läser data

Uppdatera OverviewTab, BudgetTab, TasksTab, PurchaseRequestsTab, ProjectFilesTab till att läsa via service-lagret istället för direkt. UI-rendering behöver inte ändras för fält som är null efter masking — komponenterna ska gracefully visa "—" eller dölja sektionen.
